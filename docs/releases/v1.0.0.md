# Darkbloom Control v1.0.0

A clearer native macOS dashboard for the official Darkbloom CLI.

- Opportunity: readable model cards, demand badges, RAM checks, workload counts, and a separate network-history view.
- Models: searchable local and available catalogs, expandable details, clear live state, and staged capacity controls.
- Adjust simultaneous requests and resident-model limits; preserve model-specific overrides and unrelated configuration. Save first, then restart to apply.
- Stop when idle: cancellable queue, fresh activity recheck, and protection against conflicting changes. Keep the monitor open while queued.
- Darkbloom 0.9.7 metadata, provider verification, load-failure explanations, idle-memory policy, beta features, and network/cache diagnostics.
- Preserve existing app identity, settings, history, and single-instance protection.

## Compatibility

Apple Silicon, macOS 14 or newer. Install the official Darkbloom CLI separately; it is not bundled or modified. Validated against CLI 0.9.7. Older optional diagnostics may be unavailable.

## Verification

540 tests across 70 suites passed, release build passed, and native Models/Capacity layouts were checked with live data. Staged saves and queued-stop behavior were exercised with an isolated synthetic controller; the live provider was not stopped or reconfigured for release testing.

## Signing and download

`Darkbloom-Control-v1.0.0-arm64.zip` contains version 1.0.0, build 100. The app is Developer ID–signed with hardened runtime and a secure timestamp, accepted by Apple notarization, and includes a validated stapled ticket. Gatekeeper reports **accepted — Notarized Developer ID**. `SHA256SUMS.txt` and `release-manifest.json` identify the exact distribution bytes and source commit.

## Install

Unzip the download and move Darkbloom Control.app to Applications. Quit any older monitor copy first. macOS may request first-launch confirmation and access to the external drive containing your model cache.

Queued stops require the monitor to remain running. Network demand is not a payout forecast, and customer token prices are not provider earnings. Capacity changes require a provider restart.
